# Git: ветки, коммиты, PR

Действует всегда. Подробная инструкция для людей — `docs/onboarding/05-daily-workflow.md`.

## Ветки
- `dev` — разработка и тесты, ветка по умолчанию. Сюда сливаются все задачи.
- `main` — готовый продукт. Обновляется из `dev` только по решению команды (релиз). В `main` ничего не коммить и PR не открывать.
- Ветка задачи — от свежего `dev`: `<роль>/<номер-issue>-<кратко>`, например `story/7-prologue-draft`, `shared/3-dev-process`. Для роли dev префикс — **`code/`** (`code/12-godot-sandbox`): ветку `dev/...` git не создаст, пока существует ветка `dev`.
- Мелочь без задачи (см. `tasks.md`) — ветка `chore/<кратко>`, коммиты с префиксом `chore:` без номера задачи.
- Одна основная задача = одна ветка = один PR. В `dev` напрямую не коммить.

## Перед работой
1. `git fetch` и обновить `dev`.
2. Проверить открытые PR и Issue: не правит ли кто-то те же файлы.
3. Создать ветку задачи от `dev`.

## Коммиты
- На английском, коротко, с номером задачи: `story: draft prologue (#7)`.
- Префикс — роль или `shared`.
- Агент в конце сообщения добавляет строку соавторства, если её требует его инструмент.

## Pull Request
- В `dev`, по шаблону `.github/pull_request_template.md`.
- В описании: `Closes #<основная>` и `Closes #<ИИ-подзадача>`.
- Изменились общие файлы — лейбл `shared` и список, на что они влияют.
- Слияние — **Squash and merge**, после — удалить ветку.
- Агент PR не сливает: проверяет и сливает человек.

## Нельзя
- Смешивать в одном PR изменения разных ролей.
- Удалять чужие файлы. Устаревшее — в `_archive/` с упоминанием в PR.
- Коммитить личное (`CLAUDE.local.md`, пути, ключи API).
- Файлы > 100 МБ — только после согласования.

## Бинарные файлы
- Картинки, модели, звук, исходники арта — через Git LFS, автоматически по `.gitattributes`.
- Бинарники не сливаются. Правишь такой файл — напиши в Issue «держу <файл>».
