# Как писать и менять правила

Для всех агентов (Claude, Codex и др.) и людей. Читай перед любой правкой `CLAUDE.md`, `AGENTS.md`, `.claude/rules/`, `.claude/skills/`.

## Где что лежит
- `CLAUDE.md` — каркас: стек, флоу, инструменты, **индекс правил**. Детали — не сюда, а в правила.
- `.claude/rules/<тема>.md` — одно правило = одна тема (инструмент, механика, процесс).
- `.claude/rules/lessons/<роль>.md` — набитые шишки (см. ниже).
- `.claude/skills/<имя>/SKILL.md` — скиллы (процедуры, которые агент выполняет по шагам).
- `AGENTS.md` — только вход для не-Claude агентов. Правил в нём не дублируем.
- Личное (пути, имя ПК, версии у себя) — только в `CLAUDE.local.md`, он в `.gitignore`.

## Лимиты
- Любой файл правил, `CLAUDE.md`, `AGENTS.md`, `SKILL.md` — **не больше 250 строк**. Приближаешься — дели на темы.
- Пиши коротко: правило + причина в одну строку. Без воды и повторов.

## Автоподгрузка (`paths`)
- В начале правила — frontmatter с путями, при работе с которыми правило нужно:
  ```
  ---
  paths: ["**/*.gd", "**/*.tscn"]
  ---
  ```
- Claude Code подгружает такое правило сам, только когда работает с подходящими файлами. Так контекст не раздувается.
- Без `paths` правило грузится **всегда** — только для того, что нужно в каждой задаче (git, задачи).
- Codex автоподгрузки не умеет: он читает правила по индексу в `CLAUDE.md`. Поэтому колонка «Когда подгружается» в индексе обязательна.

## Индекс — обязательно
- Добавил, переименовал или удалил правило → **обнови таблицу-индекс в `CLAUDE.md` в том же PR**. Напоминать об этом человек не должен.
- Перед PR сверь: каждый файл в `.claude/rules/` есть в индексе, и наоборот.

## Как вносить изменения
- Правила — общие файлы: отдельная задача и PR с лейблом `shared`, одобрение ещё одного участника.
- Только общее для всех участников. Никаких личных путей, имён ПК, ключей.
- Новое правило рождается из решения команды (grill-me, обсуждение в Issue), а не по инициативе агента. Предложение — в Issue с лейблом `proposal`.

## Набитые шишки (`lessons/`)
Файлы: `process.md` (всегда), `code.md`, `story.md`, `design.md` (подгружаются по своим путям).

**Когда добавлять запись:**
- человек поправил агента («не так, надо иначе»);
- одна и та же ошибка случилась второй раз;
- баг или проблема найдены уже после слияния PR.

**Формат записи** (3–4 строки):
```
### <Коротко, что случилось> (#<номер задачи>)
- Почему: <причина>
- Как избежать: <конкретное действие>
```

**Обслуживание:** файл приближается к 250 строкам → объединяй похожие записи; устойчивый вывод переноси в обычное правило (например, в `gdscript-style.md`) и удаляй запись. Добавление записи — в PR текущей задачи.
