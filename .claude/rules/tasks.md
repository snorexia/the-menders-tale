# Задачи: основные и ИИ-подзадачи

Действует всегда. Любая работа — через задачу (GitHub Issue) на доске Projects.

## Два уровня
**Основная задача — для людей.**
- Коротко и по делу: что нужно и как понять, что готово. Без технических подробностей.
- Заводит человек (или агент — после «да» человека). Лейбл роли `role:*`. Лежит на доске.
- Одна основная задача = одна роль = один результат = одна ветка = один PR.

**ИИ-подзадача — для агента.**
- Sub-issue основной задачи, лейбл `ai`, заголовок `[ИИ] <название основной>`, шаблон `.github/ISSUE_TEMPLATE/ai-task.md`.
- Заводит агент, когда берёт основную задачу в работу. На доску **не** добавляется — видна внутри основной.
- У основной задачи — **одна** ИИ-подзадача.

## Тело ИИ-подзадачи — единственный источник правды
Разделы: **Контекст** · **Решения grill-me** · **План** · **Находки и ошибки** · **Итог**.
- Контекст — только ссылки на прочитанные файлы, правила, задачи, ресерч. Без пересказа.
- Решения и Находки — **только дополняются**, не удаляются.
- План и текущее состояние — переписываются, устаревшее убирается.
- Чего нет в теле — того не существует. В конце сессии перенеси в тело всё, что решилось.
- Объём тела — до ~150 строк.

## Комментарии
- Один комментарий на рабочую сессию: **Сделано / Проблемы / Дальше**, 5–10 строк.
- Последний комментарий агента — передача дел следующему чату.

## Новый чат продолжает задачу
1. Читает тело ИИ-подзадачи.
2. Читает **все** комментарии людей (это указания) и **последний** комментарий агента.
3. Сверяет с веткой задачи: какие коммиты и изменения уже есть. Код и файлы — окончательная правда.
4. Что-то не сходится → читает всю ленту и сообщает человеку о расхождении.

## Работа выросла
- **Тот же результат, просто больше** → новые шаги в План ИИ-подзадачи.
- **Другой результат или другая роль** → остановись и спроси: «Нужна отдельная задача: …, роль …. Завести?». После «да» — новая основная задача на доске; если текущая без неё не делается — связь *blocked by*.
- **План больше ~10 шагов или тело упирается в лимит** → предложи разбить основную задачу.
- **Большая задача сразу** → родительская задача + основные задачи по ролям под ней (sub-issues), у каждой своя ИИ-подзадача.

## Статусы на доске
`Идеи` → `К работе` → `В работе` → `На проверке` → `Готово`.
- Взял задачу — назначь исполнителя, статус «В работе».
- Открыл PR — «На проверке». PR слит — «Готово».

## Команды `gh` (для агента)
- Связать подзадачу: `gh api -X POST repos/<owner>/<repo>/issues/<основная>/sub_issues -F sub_issue_id=<id подзадачи>` (id — поле `id` из `gh api repos/<owner>/<repo>/issues/<номер>`, не номер).
- Статус на доске: `gh project item-edit <номер доски> --owner <owner> --url <ссылка на issue> --field Status --value "В работе"`.
