# Сцены и узлы в Godot 4.7

Как делить на сцены, как узлы находят друг друга и общаются, как менять сцены. Язык — скилл `godot-gdscript`, интерфейс — `godot-ui`. **Архитектура проекта (папки, autoload, способ связи систем) решается в задаче #4** — здесь только приёмы движка; спорные места помечены. Источники — `.claude/skills/THIRD_PARTY.md`.

По умолчанию: одно понятие — один `.tscn`, скрипт на корне сцены, сцена содержит свои дочерние узлы, наружу — только `@export`, сигналы и несколько методов. Это же правило проекта: «одна сцена — отдельный файл, одно изменение не ломает всю игру».

## Сначала встроенное
| Нужно | Используй | Не делай |
|---|---|---|
| Повторяемый объект (клиент, предмет, панель) | отдельный `.tscn` + `instantiate()` | собирать дерево узлов кодом |
| Узел внутри своей сцены | `%УникальноеИмя` или `@onready` | длинные пути, `get_node` каждый кадр |
| Узел вне своей сцены | `@export var target: Node2D`, задать в инспекторе | `/root/Main/Level/...` |
| Сообщить группе объектов | `add_to_group` + `get_tree().call_group` | свой список-реестр |
| Ребёнок сообщает родителю | сигнал | `get_parent().foo()` |
| Состояния | `enum` + `match`; сложные — узел на состояние | пачку `is_*`-флагов с таймерами |
| Пауза | `SceneTree.paused` + `process_mode` | флаг `is_paused` в каждом скрипте |
| Смена сцены | `change_scene_to_file` / `change_scene_to_packed` | вручную `free` старой и `add_child` новой |
| Чистые данные без узла | `Resource` или `RefCounted` | наследовать `Node` ради хранения |

## Когда делить сцену
Делить: нужна в нескольких местах; больше ~15 узлов и несколько забот; можно смотреть и править отдельно; **двое людей правят одно место** — отдельные сцены меньше конфликтуют в git.
Не делить: узлы тесно связаны и деление потребует кучи сигналов; группа маленькая и используется один раз.

## Создание экземпляров
```gdscript
@export var _customer_scene: PackedScene


func spawn_customer(at: Vector2) -> void:
	var customer := _customer_scene.instantiate() as Customer
	customer.patience = 10.0
	add_child(customer)
	customer.global_position = at
```
- Начальные параметры — **до** `add_child`, тогда они видны в `_ready`. `global_position` — **после** `add_child` (до него в 2D он считается локальным, в 3D — ошибка).
- `@export var scene: PackedScene` лучше `preload("res://...")`: меняется в инспекторе и не ломается при переносе файла.
- Код создаёт узлы только когда их число задают данные (ячейки инвентаря) или это служебный узел (разовый `Timer`). Всё, что раскладывают и настраивают руками, — в `.tscn`.

## Ссылки на узлы
- Прямой ребёнок — `$Имя`; глубже — сделай имя уникальным (ПКМ → **Access as Unique Name**) и пиши `%Имя`.
- Ссылки — в типизированные `@onready`-переменные, не искать каждый кадр.
- `@export var x: Node2D` уже готов в `_enter_tree` и `_ready`, но `null` в `_init`.
- Узла может законно не быть → `get_node_or_null`.
- `%Имя` работает только внутри своей сцены (своего `owner`); узлы, добавленные кодом, без `owner` по `%Имя` не находятся.

## Связи: вызов вниз — сигнал вверх
Родитель вызывает методы детей или задаёт свойства. Ребёнок сообщает родителю сигналом и о родителе не знает. Соседи — через общего родителя или `@export` друг на друга.
```gdscript
class_name Anvil
extends Node2D

signal strike_finished(is_perfect: bool)


func strike(power: float) -> void:
	...
	strike_finished.emit(power > PERFECT_POWER)
```
- Сигналы — в прошедшем времени (`item_repaired`), обработчики — `_on_<узел>_<сигнал>` (стиль проекта).
- Сигнал сообщает «что случилось», а не приказывает. Нужно, чтобы другой что-то сделал, — вызови его метод.
- Сигналы, подключённые в редакторе, хранятся в `.tscn` и не видны при переименовании метода; `connect` в коде отслеживать проще.
- **Спорно, решается в #4:** связь далёких систем (клиент → интерфейс) через глобальную «шину событий» (autoload с сигналами). Плюс: системы не знают друг о друге. Минус: не видно, кто отправляет и кто слушает.

## Autoload
Только для глобального состояния, живущего между сценами: сохранения, настройки, переключатель сцен, прогресс сюжета. При `change_scene_to_*` autoload не удаляется.
- Общие функции — `class_name` + `static func`; общие данные — свой `Resource`. Для этого autoload не нужен.
- Из `_ready` autoload текущую сцену не получить — она ещё не загружена.
- Имена вида `GameManager`, `UIManager` запрещены стилем проекта — называй по ответственности.

## Наследование и компоненты
- Повторяющееся поведение — дочерний узел-компонент (`class_name`), хозяин передаёт его через `@export`, а не `get_parent()`.
- Наследование — для вариантов одного и того же; одного уровня обычно хватает.
- Наследованная сцена (**New Inherited Scene**) — для вариантов шаблона. Изменение структуры родительской сцены затрагивает все варианты.
- **Editable Children** у вложенной сцены хрупко: правки хранятся в сцене-хозяине и ломаются при изменении вложенной.

## Состояния
2–5 состояний с простыми переходами — `enum State` + `match`. У каждого состояния своя логика входа/выхода — узел на состояние. Все переходы — через одну функцию.

## Пауза
- `process_mode`: `INHERIT` (по умолчанию, как у родителя), `PAUSABLE`, `WHEN_PAUSED` (меню паузы), `ALWAYS` (кто переключает паузу, музыка), `DISABLED` (выключить поддерево целиком).
- `set_process(false)` выключает только `_process`, не физику и не ввод.

## Смена сцен
- После `change_scene_to_*` до конца кадра `get_tree().current_scene` равен `null`.
- Плавный переход или экран загрузки — свой переключатель (обычно autoload); решается в #4.

## Порядок и ловушки
- `_ready` детей вызывается **раньше**, чем у родителя. В `_ready` родителя дети готовы; в `_ready` ребёнка родитель — ещё нет.
- Вне дерева `get_tree()` = `null`.
- В физических обратных вызовах (`body_entered`) менять коллизии — через `set_deferred` / `call_deferred`.
- Лямбда, захватившая узел, падает после его удаления; ссылка на метод отключается сама.
- «Узел-бог» (`Level.gd` управляет камерой, интерфейсом, клиентами, таймерами) — дели по ответственности на дочерние сцены.

## Ручное написание .tscn
Агенту удобнее писать `.tscn` текстом, чем кликать в редакторе. Формат Godot 4:
```ini
[gd_scene load_steps=3 format=3]

[ext_resource type="Script" path="res://counter/counter.gd" id="1_script"]
[ext_resource type="Texture2D" path="res://counter/background.png" id="2_bg"]

[node name="Counter" type="Control"]
layout_mode = 3
anchors_preset = 15
anchor_right = 1.0
anchor_bottom = 1.0
script = ExtResource("1_script")

[node name="Background" type="TextureRect" parent="."]
layout_mode = 1
anchors_preset = 15
anchor_right = 1.0
anchor_bottom = 1.0
mouse_filter = 2
texture = ExtResource("2_bg")
expand_mode = 1
stretch_mode = 6
```
- `load_steps` = число ресурсов + 1. `uid=` можно не писать — Godot добавит при сохранении.
- `parent="."` — ребёнок корня; глубже — путь от корня: `parent="Panel/Row"`.
- Уникальное имя: `unique_name_in_owner = true` в узле.
- `@export`-свойство с типом узла задаётся путём **и** перечисляется в заголовке узла: `[node name="Hud" ... node_paths=PackedStringArray("player")]`, `player = NodePath("../Player")`. Без `node_paths` при запуске будет `null`.
- Вложенная сцена: `[ext_resource type="PackedScene" ...]` + `[node name="Anvil" parent="." instance=ExtResource("3_anvil")]`.
- После ручной правки — проверь, что проект открывается без ошибок (`--headless --quit`, см. `tools/README.md`).
