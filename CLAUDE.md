# Правила для ИИ-агентов

Этот файл читают Claude и другие агенты перед любой работой в репозитории. Люди могут его править — через pull request.

## 0. Этап проекта
Сейчас мы **до сценария**. Решения по механикам, архитектуре, структуре папок игры и арт-пайплайну **ещё не приняты**.
- Не придумывай механики, архитектуру, лор, персонажей и структуру проекта Godot по своей инициативе.
- Предложения — только по просьбе и только как черновик в Issue или в файле с пометкой `[предложение]`. Решением они становятся после одобрения команды.
- Порядок этапов — в `docs/process/workflow.md`.

## 1. Сначала контекст
- Перед задачей прочитай `README.md`, `docs/process/status.md` (где остановились), `CLAUDE.local.md` (если есть) и документы, относящиеся к задаче. Не читай всё подряд — экономь токены.
- Источник правды — файлы в `docs/`. Если задача им противоречит, спроси человека, а не выбирай сам.
- Исходная идея — `docs/game/original-brief.md`. Визуальный ориентир — `docs/reference/mockups/` (это референс, а не утверждённый арт).

## 2. Роли
Три роли: **design**, **dev**, **story**. Люди меняются ролями, поэтому роль задачи определяется лейблом `role:*` в Issue, а не тем, кто пишет.
- Работай только в рамках роли задачи. Файлы другой роли меняй лишь при явной просьбе в задаче.
- Общие файлы (`CLAUDE.md`, `README.md`, `docs/process/*`, `docs/game/original-brief.md`) меняются отдельным PR с лейблом `shared` и одобрением ещё одного участника.

## 3. Git
- Ветки: `dev` — разработка и тесты, вся работа идёт сюда. `main` — только готовый продукт (релизы); в него ничего не коммить и PR не открывать без решения команды.
- Ветка на задачу от `dev`: `<роль>/<номер-issue>-<кратко>`, например `story/7-prologue-draft`. В `dev` напрямую не коммить.
- Перед работой: обновить `dev`, создать от него ветку.
- Коммиты на английском, коротко, с номером задачи: `story: draft prologue (#7)`.
- В конце — pull request **в `dev`** по шаблону со ссылкой `Closes #7`.
- Один PR — одна задача. Не смешивай в одном PR изменения разных ролей.
- Бинарники (картинки, модели, звук, исходники арта) — только через Git LFS (настроено в `.gitattributes`). Файлы больше 100 МБ — только после согласования.
- Не удаляй чужие файлы. Устаревшее переноси в `_archive/` и упоминай в PR.

## 4. Изоляция изменений
Игра будет сюжетной, со множеством сцен. Главное правило: **одно изменение не должно ломать всю игру.**
- Одна сцена, локация или эпизод — отдельный файл или папка. Не складывай несколько сцен в один файл.
- Сюжетные тексты и данные храни отдельно от кода и сцен, чтобы сценарист правил их, не открывая движок.
- Не меняй общие (глобальные) скрипты, настройки проекта и общие ресурсы попутно с другой задачей — только отдельной задачей с лейблом `shared`.
- Перед правкой файла, который используется во многих местах, перечисли в PR, на что он влияет.
- Если файл сейчас правит другой человек (видно по открытым PR и Issue), не трогай его — напиши в задаче.

## 5. Экономия токенов
- Повторяющиеся операции (Blender, Meshy, Godot, Git) оформляй скриптом в `tools/` и переиспользуй. Перед тем как писать новый скрипт, проверь `tools/README.md`.
- Договорённости из чата переноси в `docs/` или в Issue, иначе их не существует.
- В конце сессии обнови `docs/process/status.md`: что сделано и что дальше.

## 6. Ассеты
- Имена файлов: латиница, `snake_case`, без пробелов.
- Всё сгенерированное ИИ (Meshy и др.) или взятое со стороны записывай в `docs/art/asset-log.md`: что, чем, по какому промпту, какая лицензия. Это нужно для Steam.
- Ключи API (Meshy и др.) никогда не попадают в репозиторий.

## 7. Пути
У каждого участника своя папка с репозиторием. В скриптах и файлах проекта — только относительные пути от корня репозитория.
- Личное (пути, имя ПК, версии программ, настройки MCP) — только в `CLAUDE.local.md` в корне. Он в `.gitignore`; если его нет — создай.
- В общие файлы личное не пиши: правила в репозитории должны подходить любому участнику.
