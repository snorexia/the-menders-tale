# Словарик

Термины, которые встречаются в проекте, — простыми словами. Новое непонятное слово — попроси Claude добавить его сюда.

## Git и GitHub
- **Репозиторий (репо)** — папка проекта со всей историей изменений. Наш — `snorexia/the-menders-tale` на GitHub.
- **Git** — программа, которая запоминает каждую версию файлов. Можно посмотреть, кто и что менял, и откатиться.
- **GitHub** — сайт, где хранится общий репозиторий, задачи и обсуждения.
- **Клонировать (clone)** — скачать репозиторий к себе на ПК.
- **Ветка (branch)** — отдельная копия проекта для работы, которая не мешает остальным. Сделал задачу в своей ветке — потом влил в общую.
- **`dev`** — общая ветка разработки и тестов. Все задачи вливаются сюда. Ветка по умолчанию.
- **`main`** — ветка готового продукта (релизы). Обновляется только по решению команды.
- **Коммит (commit)** — сохранённая порция изменений с подписью «что сделано».
- **Push** — отправить свои коммиты на GitHub.
- **Fetch / Pull** — проверить, есть ли новое на GitHub / забрать это новое к себе.
- **PR (Pull Request, запрос на слияние)** — просьба «проверьте мои изменения и влейте их в `dev`». Видно, какие файлы и строки изменились, можно оставить комментарии.
- **Review (ревью, проверка)** — другой участник смотрит PR и одобряет (**Approve**) или просит исправить.
- **Merge (слияние)** — влить изменения из ветки в `dev`. **Squash and merge** — влить одним аккуратным коммитом.
- **Конфликт** — двое изменили одно место по-разному, Git не знает, что оставить. Решает человек или агент.
- **Git LFS** — дополнение Git для больших файлов (картинки, модели, звук). Работает автоматически.
- **`.gitignore`** — список файлов, которые не попадают в репозиторий (например, личный `CLAUDE.local.md`).

## Задачи
- **Issue (задача)** — карточка с описанием работы на GitHub. У каждой есть номер: #2, #7.
- **Основная задача** — для людей: что нужно сделать и как понять, что готово.
- **ИИ-подзадача (sub-issue)** — подзадача внутри основной, которую ведёт агент: что прочитал, какие решения приняты, план, ход работы. Помечена `[ИИ]` и лейблом `ai`.
- **Лейбл (label)** — цветная метка на задаче: роль (`role:dev`), тип (`bug`, `story`), `shared` — общие файлы.
- **Доска (Projects)** — колонки со статусами: Идеи → К работе → В работе → На проверке → Готово.
- **Blocked by** — связь «эту задачу нельзя сделать, пока не сделана другая».

## ИИ и правила
- **Claude Code** — ИИ-агент от Anthropic, работает прямо с файлами проекта. У нас — для кода, правил, задач.
- **Codex / GPT** — ИИ-агент от OpenAI. У нас — для арта.
- **`CLAUDE.md`** — главный файл правил, агент читает его первым.
- **`AGENTS.md`** — вход для других агентов (Codex): «прочитай CLAUDE.md».
- **`CLAUDE.local.md`** — личные заметки агента о твоём ПК. В репозиторий не попадает.
- **Правила (`.claude/rules/`)** — короткие файлы по темам: стиль кода, git, задачи. Агент читает только нужные.
- **Скилл (skill)** — готовая процедура для агента. Например, **grill-me**.
- **grill-me** — планирование вопросами: агент задаёт вопросы по одному, пока всё не станет ясно, и только потом делает.
- **Набитые шишки (`lessons/`)** — записи об ошибках, чтобы агенты их не повторяли. Разделены по ролям.
- **Контекст** — всё, что агент «держит в голове» в одном чате. Он ограничен, поэтому правила короткие (до 250 строк).
- **MCP** — способ подключить программу (например, Blender) к ИИ, чтобы агент мог ей управлять.
- **`gh` (GitHub CLI)** — программа, через которую агент работает с задачами и PR.

## Игра и Godot
- **Godot** — игровой движок, в котором делаем игру.
- **GDScript** — язык программирования Godot, похож на Python.
- **Сцена (`.tscn`)** — собранный объект или экран игры: кузня, прилавок, кнопка.
- **Узел (node)** — кирпичик сцены: картинка, кнопка, звук, область.
- **Сигнал** — сообщение «что-то произошло» (`item_repaired`), на которое другие части игры могут отреагировать.
- **Фича** — одна часть игры: кузня, верстак, диалог с клиентом.
- **Плагин / аддон (`addons/`)** — готовое дополнение к Godot от других разработчиков (например, для диалогов).
- **Песочница (`sandbox/`)** — пробные проекты Godot для обучения и проверки инструментов. Не игра: всё оттуда можно выбросить.
- **gdlint / gdformat** — программы, которые проверяют и выравнивают код GDScript по нашему стилю.
- **Переменная окружения** — именованная настройка Windows, которую читают программы (например, `GODOT_PATH` — где лежит Godot).
- **Node.js** — среда для запуска программ на JavaScript; на ней работают многие MCP-серверы.

## 3D и арт
- **Полигоны** — плоские грани, из которых состоит 3D-модель. Чем их больше, тем тяжелее модель.
- **Децимация** — автоматическое уменьшение числа полигонов (в Blender — модификатор Decimate).
- **Ретопология** — аккуратная перестройка сетки модели с меньшим числом полигонов и ровной структурой.
- **Запекание (baking)** — перенос мелких деталей с тяжёлой модели в текстуру лёгкой модели.
- **Текстура** — картинка, которая «натягивается» на модель: цвет, рельеф, блеск.
- **Мокап (mockup)** — концепт-картинка экрана, ориентир, а не готовый арт.
