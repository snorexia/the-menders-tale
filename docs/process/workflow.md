# Как мы работаем

Короткий обзор для людей. Подробные правила — `.claude/rules/` (индекс в `CLAUDE.md`), пошаговые инструкции — `docs/onboarding/`.

## Этапы проекта
Двигаемся по порядку. Следующий этап начинается, когда команда согласна с результатом предыдущего.

1. **Правила и инфраструктура.** Репозиторий, задачи, правила, инструменты.
2. **Сценарий и вектор игры** ← сейчас. Сюжет, персонажи, основные эпизоды, что делает игрок.
3. **Архитектура.** Как делим игру на сцены и файлы, где лежат тексты и данные, как устроен проект Godot. Строится по сценарию.
4. **Прототип.** Первый играбельный эпизод.
5. **Производство.** Сцены, арт, тексты — параллельно, по задачам.

Решения каждого этапа записываются в `docs/` через PR.

## Роли
Роль задачи — лейбл в Issue. Люди могут меняться ролями.

| Роль | Лейбл | Отвечает за | Сейчас |
|---|---|---|---|
| Разработка | `role:dev` | Godot, механики, код, сборка | snorexia |
| Сюжет | `role:story` | Сценарий, персонажи, диалоги, тексты | dobraykduff1234-glitch |
| Дизайн | `role:design` | Арт, модели, интерфейс, анимации | Weh2 |

## Задачи
- **Любая работа — задача (Issue)** на доске Projects: `Идеи` → `К работе` → `В работе` → `На проверке` → `Готово`.
- **Основная задача** — для людей: коротко, что нужно и как понять, что готово.
- **ИИ-подзадача** — внутри основной: что агент прочитал, какие решения приняты, план, ход работы. Её можно открыть и проверить.
- Лейблы: роль (`role:*`), тип (`feature`, `bug`, `art`, `story`, `docs`, `shared`, `proposal`), `ai` — ИИ-подзадача.
- Подробно — `.claude/rules/tasks.md`.

## Планирование — grill-me
Перед каждой задачей агент задаёт вопросы по одному, с вариантами и рекомендацией, пока всё не станет ясно. Итог — в ИИ-подзадаче. Работа начинается после одобрения плана человеком.

## Ветки
- `dev` — разработка и тесты, все задачи сливаются сюда.
- `main` — готовый продукт, только по решению команды.
- Одна задача — одна ветка — один PR в `dev`. Подробно — `.claude/rules/git-workflow.md`.

## Как не мешать друг другу
- **Одна задача — один PR — одна роль.**
- **Одно изменение не ломает всю игру.** Каждая сцена, локация или эпизод — в отдельном файле или папке. Тексты и сюжетные данные — отдельно от кода.
- **Общее меняем отдельно** — задачей с лейблом `shared`.
- **Бинарные файлы не сливаются.** Правишь `.blend`, `.kra`, сцену — напиши в Issue «держу <файл>».
- Мелкие частые PR лучше больших редких.
