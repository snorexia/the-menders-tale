# Как мы работаем

## Этапы проекта
Двигаемся по порядку. Следующий этап начинается, когда команда согласна с результатом предыдущего.

1. **Правила и инфраструктура** ← сейчас. Репозиторий, задачи, правила, инструменты.
2. **Сценарий и вектор игры.** Сюжет, персонажи, основные эпизоды, что делает игрок.
3. **Архитектура.** Как делим игру на сцены и файлы, где лежат тексты и данные, как устроен проект Godot. Строится по сценарию.
4. **Прототип.** Первый играбельный эпизод.
5. **Производство.** Сцены, арт, тексты — параллельно, по задачам.

Решения каждого этапа записываются в `docs/` через PR.

## Роли
Люди меняются ролями. Роль задачи — лейбл в Issue.

| Роль | Лейбл | Отвечает за |
|---|---|---|
| Дизайн | `role:design` | Арт, модели, интерфейс, анимации |
| Разработка | `role:dev` | Godot, механики, код, сборка |
| Сюжет | `role:story` | Сценарий, персонажи, диалоги, тексты |

## Задачи — GitHub Issues + Projects
- **Любая работа — Issue.** Обсуждение по задаче — в комментариях к ней, а не в мессенджере.
- Доска Project: `Идеи` → `К работе` → `В работе` → `На проверке` → `Готово`.
- Лейблы: роль (`role:design`, `role:dev`, `role:story`), тип (`feature`, `bug`, `art`, `story`, `docs`, `shared`, `proposal`).
- Взял задачу — назначь себя и перенеси в «В работе».

## Ветки
| Ветка | Для чего |
|---|---|
| `dev` | Разработка и тесты. Сюда сливаются все задачи. |
| `main` | Готовый продукт. Обновляется из `dev` только по решению команды (релиз). |
| `<роль>/<номер>-<кратко>` | Одна задача, ответвляется от `dev`. |

## Как вносить изменения
1. Переключись на `dev` и обнови его (GitHub Desktop: **Current branch** → `dev`, затем **Fetch origin** → **Pull**).
2. Создай от `dev` ветку `<роль>/<номер>-<кратко>`, например `story/7-prologue-draft`.
3. Работай, делай коммиты.
4. **Push** → **Create Pull Request** в `dev`. В описании `Closes #7`.
5. Хотя бы один другой участник смотрит PR и одобряет.
6. Слияние — **Squash and merge**.

Ветки `dev` и `main` защищены: изменения только через PR.

## Как не мешать друг другу
- **Одна задача — один PR — одна роль.**
- **Одно изменение не ломает всю игру.** Каждая сцена, локация или эпизод — в отдельном файле или папке. Тексты и сюжетные данные — отдельно от кода.
- **Общее меняем отдельно.** Глобальные скрипты, настройки проекта, общие ресурсы и эти правила — только отдельной задачей с лейблом `shared`.
- **Бинарные файлы не сливаются** (сцены движка, `.blend`, `.kra`). Если правишь такой файл, напиши в Issue «держу <файл>», чтобы двое не правили одно и то же.
- Мелкие частые PR лучше больших редких.
- Начинаешь работу — **Pull**. Закончил — **Push** и обнови `docs/process/status.md`.

## Работа через Claude
Каждый работает через Claude Code со своего ПК, в своей папке репозитория. Хороший запрос:
> «Возьми Issue #7, роль story. Сделай черновик пролога, открой PR.»

Claude читает `CLAUDE.md` и `CLAUDE.local.md` (личные заметки о твоём ПК, в git не попадают), работает в ветке от `dev` и открывает PR в `dev`. Проверяет его человек.

## Общение
- Discord или Telegram (выбрать один) — быстрые вопросы, созвоны, демонстрация экрана.
- Решение принято в чате — перенеси его в Issue или `docs/`.

## Ассеты
- Имена: латиница, `snake_case`.
- Бинарники через Git LFS — автоматически по `.gitattributes`. На каждом ПК один раз: `git lfs install`.
- Сгенерированное ИИ или взятое со стороны — в `docs/art/asset-log.md`.
